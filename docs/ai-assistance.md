# AI-помощник каталога

Базовый анализ описания и 3–7 вопросов используют существующий AI service. Карточка
собирается из исходного текста и ответов без добавления фактов. Публикация требует
подтверждения бизнеса; выбор команд остаётся ручным.

Дополнения доступны через `/api/v1/catalog`:

| Запрос | Поведение |
| --- | --- |
| `POST /tasks/{id}/rating-advice` | Объяснение сохранённого RatingBreakdown, конкретные рекомендации с учётом фиксированных весов. Не изменяет рейтинг. |
| `GET ?skills=Python&interests=analytics` | Сортировка по совпадению ключевых слов, затем рейтингу; выполняется до пагинации. Ничего не скрывает. |
| `POST /tasks/{id}/proposals/{proposal_id}/analysis` | Summary идеи и плана, пробелы и вопросы. Содержимое ссылки не загружается, команды не ранжируются и не выбираются. |
| `POST /drafts/{id}/similar` | Семантическое сравнение с 50 опубликованными задачами с наивысшим рейтингом, до 5 похожих задач с причинами. Проверяются только ID предоставленных кандидатов. |
| `POST /drafts/{id}/next-question` | Уточняет первый неотвеченный вопрос с учётом сохранённых ответов. Сохраняет набор минимум из трёх вопросов; проверяет изменение истории во время запроса. |
| `POST /drafts/{id}/title` | Предлагает редактируемый заголовок из описания и сохранённых ответов; сам не создаёт и не публикует карточку. |

Все POST выше доступны только бизнесу-владельцу. Публичная сортировка работает без
ИИ. Навыки и интересы вводятся в каталоге и сохраняются в состоянии текущей сессии
интерфейса; отдельной постоянной модели Team в текущем MVP нет.

На странице создания включён пошаговый режим. После сохранения ответа следующий
вопрос уточняется через ИИ. Можно переключиться на полный список. Если ИИ недоступен,
сохранённые ответы остаются, доступны исходные вопросы и повторная попытка. Похожесть
проверяется после создания черновика и вручную кнопкой. Пустой заголовок генерируется
при сборке карточки; готовую карточку бизнес проверяет перед публикацией.

Используются существующие `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_MAX_OUTPUT_TOKENS`
и AI service. Новые зависимости и миграции не нужны. Вызовы советов платные по тарифу
настроенного провайдера, автоматического кеша нет. Сервис проверяет JSON-схемы,
не логирует содержимое и ключи, передаёт авторизацию и не возвращает ошибки провайдера.

Если ИИ не подключён, проверьте наличие непустого `OPENAI_API_KEY` в локальном
`backend/.env` и перезапустите backend после изменения. Каталог сохраняет безопасные
коды AI service: `ai_not_configured` (ключ не задан), `ai_configuration_error`
(ошибка доступа), `ai_rate_limit`, `ai_timeout` и ошибки генерации. Интерфейс переводит
их на русский, казахский и английский; исходные тела ошибок провайдера не передаются.
Ошибка проверки похожести не означает отсутствие совпадений и не блокирует сборку
карточки с заголовком, введённым вручную.

Ограничения MVP: keyword matching без embeddings и морфологии; похожесть проверяется
по названию и первым 200 символам контекста 50 кандидатов, поэтому не гарантирует
нахождение всех дублей. Суммарный JSON-вход AI service ограничен 32 000 символами:
слишком длинные материалы отклоняются, а не обрезаются незаметно. Советы ИИ могут
содержать ошибки — фиксированные баллы и бизнес-решения не зависят от их текста.

Проверки: `backend/.venv/Scripts/python.exe -m pytest` в `backend/catalog_service`;
`node --test tests/ai-assistance.test.mjs` и `npm run typecheck` в `frontend`.

Расширенная регрессия: `npm run test:unit` запускает все локальные frontend-тесты;
`.venv/Scripts/python.exe scripts/run_tests.py -p no:cacheprovider` из `backend`
проверяет все пять серверных сервисов. Тесты AI используют подменённого провайдера
и не делают платных запросов. Проверяются права доступа, невалидный JSON, ошибки
сети, граница длины запроса, сохранность данных при сбоях, изменение черновика
во время генерации и два одновременных уточнения через независимые сессии БД.
Уточнение сохраняет поле исходного вопроса; вопрос с локально набранным ответом
не заменяется. Для PostgreSQL-тестов миграций нужен `CATALOG_TEST_POSTGRES_URL`.
