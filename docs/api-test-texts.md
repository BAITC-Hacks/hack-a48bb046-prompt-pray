# Тексты для ручной проверки API

В [api-test-texts.json](api-test-texts.json) — 32 независимых примера: 26 бизнес-описаний
и 6 проверок контракта, включая язык по умолчанию. Все организации, показатели и контакты
в примерах вымышлены. Набор ничего не публикует и не запускает автоматически.

Каждый элемент содержит `id`, название сценария, готовое тело запроса `request`,
ожидаемый HTTP-статус создания черновика `expected_status` и подсказку `check`.
В API отправляйте только объект `request`: служебные поля набора не входят в контракт.

## Как использовать

1. Авторизуйтесь под бизнес-аккаунтом и получите access token.
2. Отправьте `request` выбранного примера в `POST /api/v1/catalog/drafts`.
3. Для успешного запроса проверьте статус 201, сохранённое описание и `locale`.
4. С полученным `id` вызовите `POST /api/v1/catalog/drafts/{id}/questions`
   с тем же токеном. Тело запроса не требуется.
5. Проверьте минимум 3 вопроса, соответствие языку и пункту `check`.
   Точные формулировки AI могут различаться: оценивайте смысл, а не совпадение строк.

Пример в PowerShell из корня репозитория, с уже заданным `$accessToken`:

```powershell
$cases = Get-Content -Raw -Encoding UTF8 ./docs/api-test-texts.json | ConvertFrom-Json
$case = $cases | Where-Object { $_.id -eq 'ru-06' }
$headers = @{ Authorization = "Bearer $accessToken" }
$body = [System.Text.Encoding]::UTF8.GetBytes(($case.request | ConvertTo-Json -Depth 5))
$draft = Invoke-RestMethod -Method Post `
  -Uri 'http://localhost:8000/api/v1/catalog/drafts' `
  -Headers $headers -ContentType 'application/json; charset=utf-8' -Body $body
Invoke-RestMethod -Method Post `
  -Uri "http://localhost:8000/api/v1/catalog/drafts/$($draft.id)/questions" `
  -Headers $headers
```

Каждый запуск примера создаёт новый черновик. Для повторной независимой проверки генерации
создавайте новый черновик: повторный вызов вопросов для того же `id` возвращает сохранённые
вопросы. Отрицательные примеры ожидают 422; `Invoke-RestMethod` сообщит об HTTP-ошибке,
и переходить к генерации вопросов для них не нужно. Статусы предполагают работающие
сервисы и действующий токен нужной роли; генерация дополнительно требует доступного AI.

## Что покрывает набор

| Примеры | Проверка |
|---|---|
| `ru-01`–`ru-04` | Мало информации, опечатки, отсутствие данных или определённой цели |
| `ru-05`, `en-02` | Подробное описание, сохранение чисел, ограничений и контактов |
| `ru-06`–`ru-09` | Противоречия, несколько задач и неизмеримые критерии |
| `ru-10`–`ru-15` | Доступ к данным, малая выборка, связь, доступность, бюджет, отрицания |
| `ru-16`–`ru-19` | Переносы, Unicode, цитаты с инструкциями и текст с разметкой |
| `ru-20` | Сохранение ручного выбора команды представителем бизнеса |
| `kk-01`–`kk-03`, `en-01`–`en-03` | Языки `kk` и `en`, несовпадение языка описания с `locale` |
| `validation-01`–`validation-06` | Значение языка по умолчанию и ошибки валидации |

`check` описывает ожидаемое поведение для ручной оценки, а не результат уже выполненного
запроса. Создание черновика проверяет входные данные; качество уточнений оценивается после
отдельного вызова вопросов. Проверка исполнения разметки требует просмотра в интерфейсе,
а проверка ручного выбора команды — отдельного сценария откликов и решений.

Рейтинг появляется у карточки и зависит от заполнения её семи полей. Длинное описание
черновика само по себе не гарантирует 100 баллов. Сборка карточки, подтверждение,
публикация и решения по откликам описаны в [контракте каталога](catalog-api.md).
