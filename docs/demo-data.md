Подготовил: Улан. Все организации, команды, показатели и договорённости вымышлены.
Набор загружается через API без вызовов AI, очистки базы и автоматического выбора команд.

## Состав на новой базе

| Сущность | Количество | Что показать |
|---|---:|---|
| Отдельные черновики | 5 | Разная полнота: запись клиентов, пекарня, учебный центр, теплица, доставка; ru/kk/en |

Дополнительно у каждой карточки есть исходный TaskDraft, поэтому API возвращает
10 черновиков: 5 без карточки и 5 со ссылкой `card_id`.
Отрасль указана в JSON-наборе и тексте сценария, отдельного поля отрасли в API пока нет.

| Карточка | Рейтинг | Уровень | Полных откликов |
|---|---:|---|---:|
| Дашборд продаж кофейни | 100 | Приоритетная | 2 |
| Карта пунктов приёма вторсырья | 80 | Готовая | 1 |
| Учёт заявок мастерской | 60 | Рабочая | 1 |
| Популярность книг библиотеки | 40 | Рабочая | 0 |

Баллы рассчитывает backend по обычной формуле; seed не записывает рейтинг напрямую.
Неполные поля намеренно отсутствуют. На задачу с 20 баллами уже есть отклик.
Решений по командам seed не создаёт: бизнес выбирает вручную.

## Загрузка

`start.bat` / `start.sh` создают данные при `ENV=development`, если не указан `--no-demo`.
Для уже работающего backend выполните из папки `backend`:

```powershell
.\.venv\Scripts\python.exe scripts/seed_demo.py
```

Адреса можно задать явно:

```powershell
.\.venv\Scripts\python.exe scripts/seed_demo.py --base-url http://127.0.0.1:8000 --frontend-url http://127.0.0.1:3000
```

`--frontend-url` задаёт адрес для **новых** ссылок на макеты; существующие отклики
не переписываются. Все пять макетов находятся в
[`frontend/public/demo/prototypes.html`](../frontend/public/demo/prototypes.html),
каждая ссылка открывает свой раздел. Это честно обозначенные статические примеры,
без обработки реальных данных и без имитации работающего AI.

Seed сохраняет соответствие ключей набора и ID в `backend/data/demo-seed.json`
(не коммитится). Повторный запуск с тем же адресом gateway сохраняет изменённые
описания, карточки, снятую публикацию и решения бизнеса. Если карточка снята с
публикации, связанные новые отклики пропускаются и перечисляются в отчёте.
Сохраняйте файл реестра вместе с базой; без него поиск старых черновиков возможен
только по исходному описанию, а изменённое описание нельзя надёжно распознать.

При обновлении прежнего демо сохраняются три старые карточки и два старых отклика,
добавляются недостающие карточки/черновики и пять полных откликов. Поэтому обычно
получается 7 откликов. Содержимое старых карточек также остаётся прежним.
Если у демоаккаунта другой пароль или роль, seed завершится ошибкой и не заменит его.
Загрузка не является общей транзакцией: уже созданные записи сохраняются при ошибке;
повторный запуск добавляет отсутствующие. Если сбой произошёл после сборки карточки,
но до публикации, подтвердите и опубликуйте её вручную как `user1`.

## Проверка перед показом

1. Откройте каталог: пять демокарточек, рейтинги по убыванию.
2. Войдите как `user1`: в аккаунте есть пять черновиков без карточек.
3. Откройте кофейню: сравните Data Qadam и Insight Lab, перейдите по ссылкам на макеты.
4. Откройте отзывы магазина: низкий рейтинг не мешает видеть отклик Til Analytics.
5. Выберите одну, несколько или ни одной команды вручную; обновите страницу.

Автоматическая проверка на изолированной SQLite:

```powershell
python scripts/run_tests.py catalog_service -k demo_seed
```

Проверяются объём, ru/kk/en, реальные расчёты рейтинга, отклик на 20 баллов,
ссылки на макеты, отсутствие автоматического выбора и сохранность правок при повторе.
