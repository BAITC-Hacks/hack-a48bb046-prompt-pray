# AI Sana — от бизнес-потребности до студенческого проекта

MVP команды **Prompt&Pray**: бизнес описывает проблему своими словами, AI помогает
уточнить недостающие сведения, а платформа собирает редактируемую карточку задачи.
После подтверждения бизнесом она попадает в открытый каталог. Студенческие команды
предлагают решения, бизнес сравнивает отклики и вручную выбирает исполнителей.

Продукт решает проблему неполных технических заданий: командам заранее видны контекст,
ожидаемый результат, материалы и критерии успеха. Геймификация мотивирует **бизнес**
улучшать описание: полнота карточки даёт рейтинг от 0 до 100 и влияет на порядок в каталоге.
Низкий рейтинг не скрывает опубликованную задачу и не блокирует отклики.
Автоматического назначения команды нет: можно выбрать одну, несколько или ни одной.

## Быстрый запуск

Нужны **Python 3.10+**, **Node.js 22** и **pnpm 12.4.1** (версия закреплена
в `frontend/package.json`). При первой установке зависимостей нужен интернет.
Для локального запуска используется SQLite, Docker не нужен.
Команды ниже выполняются из корня скачанного или клонированного репозитория.

### 1. Backend — первый терминал

Windows PowerShell:

```powershell
cd backend
.\start.bat
```

Linux / macOS:

```bash
cd backend
bash start.sh
```

Скрипт создаёт `.venv`, устанавливает зависимости, копирует `.env.example` в `.env`,
если файла ещё нет, и запускает сервисы. Дождитесь сообщения «Бэкенд запущен».
Данные сохраняются в `backend/data/` между запусками.
В режиме `development` автоматически создаются демоаккаунты и задачи;
флаг `--no-demo` отключает их создание.

### 2. Frontend — второй терминал

```bash
cd frontend
pnpm install
pnpm dev
```

По умолчанию frontend обращается к gateway на `http://127.0.0.1:8000`.
Для стандартного запуска frontend `.env` не обязателен. Если адрес gateway другой,
скопируйте `frontend/.env.example` в `frontend/.env` и измените `NUXT_GATEWAY_URL`.

| Что открыть | Адрес |
|---|---|
| Приложение | http://localhost:3000 |
| Публичный каталог | http://localhost:3000/catalog |
| Вход | http://localhost:3000/login |
| Состояние backend | http://localhost:8000/health |
| Swagger каталога, включая схемы запросов | http://localhost:8004/api/v1/docs |
| Swagger авторизации | http://localhost:8001/api/v1/docs |

Для остановки нажмите `Ctrl+C` в обоих терминалах.
Запуск с PostgreSQL и Docker описан в [backend/README.md](backend/README.md).

### 3. AI для новых задач

Для генерации уточняющих вопросов укажите собственный `OPENAI_API_KEY`
в `backend/.env`, при необходимости настройте `OPENAI_MODEL` и перезапустите backend.
Ключ используется только на сервере; не добавляйте `.env` в git.

**Без ключа можно проверить каталог, редактирование демокарточек, рейтинг, публикацию,
отклики и ручной выбор.** Генерация вопросов требует доступного AI-провайдера:
без него интерфейс показывает ошибку `ai_unavailable`, а сохранённый черновик
остаётся доступен для повторной попытки. Демо-задачи — заранее подготовленные
учебные примеры, а не результат вызова AI.

## Проверка решения для жюри

### Демонстрация без AI-ключа

На свежей локальной базе доступны следующие учётные записи:

| Логин | Роль | Пароль |
|---|---|---|
| `user1` | Бизнес, владелец демозадач | `password123` |
| `user2` | Студент | `password123` |
| `user3` | Студент | `password123` |

Это публичные данные только для локального демо. Вход поддерживает имя пользователя
или email (например, `user1@demo.example.com`).

1. Откройте `/catalog` без входа. В свежей базе есть три опубликованные задачи
   с разной полнотой описания: про продажи кофейни, заявки мастерской и отзывы магазина.
   Проверьте сортировку по рейтингу и доступность карточки с низким рейтингом.
2. Войдите как `user1`, откройте задачу про отзывы магазина. Дополните пустые поля
   и нажмите **«Сохранить и пересчитать рейтинг»**. Рейтинг должен вырасти.
   Изменение снимает публикацию до нового подтверждения владельцем.
3. Нажмите **«Подтверждаю — опубликовать»**. Проверьте, что обновлённая карточка
   снова доступна в публичном каталоге.
4. Выйдите и войдите как `user2`. Откройте опубликованную задачу про отзывы,
   заполните форму отклика: идею, план и при наличии ссылку на прототип.
   В MVP команда определяется по текущему аккаунту. Отправьте отклик.
5. Снова войдите как `user1`: отклик должен быть виден владельцу задачи.
   На задаче **«Демо: дашборд продаж кофейни»** уже подготовлены два отклика
   для сравнения. Отметьте выбранные предложения и сохраните решение.
   Выбор происходит только после действия бизнеса; допустим и пустой выбор.
6. Обновите страницу: карточка, отклики и решение должны сохраниться.

Повторный запуск backend сохраняет изменения демоданных, поэтому после предыдущей
демонстрации состояние может отличаться от начального.

### Полный путь с AI-ключом

1. Войдите как `user1`, откройте `/tasks/new` и введите, например:
   «У нас кофейня. Продажи ведём в таблице, хотим понимать, какие товары приносят выручку».
2. Нажмите **«Сохранить и получить вопросы»**. Ожидается минимум три уточняющих
   вопроса о недостающих сведениях. Ответьте, используя только известные вам факты,
   и нажмите «Сохранить ответ» для каждого заполненного вопроса.
3. Укажите название и нажмите **«Собрать карточку»**. Проверьте перенесённые сведения,
   при необходимости отредактируйте поля. Карточка ещё не опубликована.
4. Проверьте рейтинг и нажмите **«Подтверждаю — опубликовать»**.
   Затем повторите отправку отклика и ручной выбор из предыдущего сценария.

AI используется для анализа полноты и генерации вопросов. Карточка собирается
из введённого описания и ответов; перед публикацией результат проверяет человек.
Описанный выше путь включает AI-уточнение. API также позволяет собрать карточку
без вопросов и ответов, из описания и явно переданных полей. Минимум три вопроса
обязателен для результата генерации, но не является условием публикации.
Подтверждение владельцем обязательно в обоих случаях.

## Как считается рейтинг

| Заполненное поле | Баллы |
|---|---:|
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |

Уровни: **0–39 — черновик**, **40–69 — рабочая**, **70–89 — готовая**,
**90–100 — приоритетная**. Баллы пересчитываются при редактировании.
Рейтинг описывает полноту задания, а не качество студенческой команды.

## Технологии и устройство

| Слой | Технологии и назначение |
|---|---|
| Интерфейс | Nuxt 4, Vue 3, TypeScript, Nuxt UI 4, Tailwind CSS 4 |
| Сервер frontend | Nitro: проксирование API и сессии, refresh-токен в httpOnly cookie |
| Backend | Python, FastAPI, Pydantic; API Gateway и отдельные сервисы авторизации, каталога и AI |
| Хранение | SQLAlchemy, SQLite для локального демо, PostgreSQL для Docker |
| AI | OpenAI Responses API для уточняющих вопросов |
| Проверки | pytest, интеграционные Node.js-тесты, ESLint, vue-tsc |

Путь запроса: **браузер → Nuxt/Nitro → API Gateway → сервис → база данных**.
AI-сервис обращается к внешнему провайдеру. Backend также содержит `example_service`
как пример CRUD для разработки.

| Каталог | Содержимое |
|---|---|
| [`frontend/`](frontend/README.md) | Интерфейс, серверный прокси, команды сборки |
| [`backend/`](backend/README.md) | Сервисы, запуск, окружение, базы данных |
| [`backend/catalog_service/`](backend/catalog_service/README.md) | Предметная логика задач, рейтинга, откликов и решений |
| [`docs/catalog-api.md`](docs/catalog-api.md) | Контракт каталога и права доступа |
| [`docs/`](docs/README.md) | Архитектура и стандарты API |

## Автоматические проверки

После установки зависимостей и первого запуска backend, из корня репозитория
в Windows PowerShell:

```powershell
cd backend
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe scripts/run_tests.py
.\.venv\Scripts\python.exe scripts/test_frontend.py
```

Linux / macOS:

```bash
cd backend
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python scripts/run_tests.py
.venv/bin/python scripts/test_frontend.py
```

`run_tests.py` запускает тесты сервисов по отдельности, включая проверки доменного
сценария и AI с подменённым провайдером. `test_frontend.py` требует установленных
frontend-зависимостей и запускает отдельные Nuxt/backend-процессы на свободных портах
с временными SQLite-базами: проверяет сессию, карточку, публикацию, отклики и выбор.
AI-ключ для этих проверок не нужен. Успешное завершение — код выхода `0`.

В отдельном терминале из корня репозитория:

```bash
cd frontend
pnpm lint
pnpm typecheck
pnpm test:proxy
pnpm build
```

## Если что-то не запускается

| Симптом | Что проверить |
|---|---|
| `pnpm` не найден | Установите pnpm версии, указанной в `frontend/package.json`, и откройте новый терминал |
| Backend сообщает о занятых портах | Освободите порты 8000–8004 или настройте их в `backend/.env`; при смене gateway обновите `NUXT_GATEWAY_URL` |
| Каталог не загружается | Проверьте `http://localhost:8000/health` и логи первого терминала |
| Нет демоданных | Дождитесь сообщения «Демоданные готовы»; проверьте `ENV=development`, отсутствие `--no-demo` и ошибок создания демо в логах |
| Вопросы не генерируются | Проверьте ключ, модель и доступ к AI-провайдеру; после изменения `.env` перезапустите backend и повторите уточнение |

## Границы MVP

Основной демонстрационный путь — каталог и работа с задачами. В репозитории также
сохранились страницы и материалы исходного Nuxt SaaS Template, например блог и тарифы;
они не являются реализованными бизнес-функциями платформы.
В MVP нет real-time чата, полноценного проектного трекера и обучения собственной модели.
Мобильная адаптация и сложное управление ролями не входят в объём MVP.
