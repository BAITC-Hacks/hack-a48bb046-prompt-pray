# T-21: браузерная проверка MVP

Из `backend` подготовьте Python 3.12+ virtualenv `.venv` и установите зависимости:

```sh
python -m venv .venv
.venv/Scripts/python -m pip install -r auth_service/requirements.txt -r catalog_service/requirements.txt -r api_gateway/requirements.txt
```

На Linux используйте `.venv/bin/python`. Затем из `frontend`:

```sh
pnpm install
pnpm exec playwright install chromium
pnpm lint
pnpm typecheck
pnpm build
pnpm test:browser
```

`BROWSER_TEST_PYTHON` позволяет указать другой Python с зависимостями backend.
Если Chromium скачать не удалось, можно использовать установленный Chrome:
PowerShell: `$env:BROWSER_TEST_CHANNEL='chrome'`; bash: `export BROWSER_TEST_CHANNEL=chrome`.
Запуск всегда создаёт отдельные профили браузера, не использует личные сессии.

Runner поднимает auth, catalog, gateway и **собранный** Nuxt на свободных локальных
портах, создаёт временные SQLite-базы и удаляет их при завершении. Не подключайте
тест к рабочей базе. Сервисы закрываются и при падении теста; последние строки
их логов выводятся для диагностики. Обычный запуск `scripts/test_frontend.py`
без `--browser` сохраняет прежние API-проверки.
После браузерного прогона на том же стенде выполняются регрессионные проверки
авторизации и каталога, включая refresh-сессию и права доступа.

AI заменён только на границе HTTP-сервиса: локальный fixture проверяет инструкцию
об определении языка по описанию и возвращает три фиксированных вопроса.
Отдельный запрос с маркером fixture-unavailable отвечает 503: проверяется
сохранение резервных вопросов после отказа AI. Настоящие UI, Nitro, авторизация, каталог, миграции, рейтинг и база
работают без подмен. Внешний AI и API-ключи не нужны.

Для каждого ru/kk/en проверяются:

- главная, SSR, отсутствие hydration mismatch, cookie и язык после reload;
- вход по имени, ошибки API и валидации, смена языка без потери ввода/URL;
- черновик с автоматически определённым locale и три вопроса на языке описания;
- сохранение ответа и повторное открытие, неизменность пользовательского текста;
- сборка карточки с рейтингом 30, отсутствие её в каталоге до подтверждения;
- публикация и переход из каталога, два студенческих отклика через формы;
- отсутствие автоматического решения и органов выбора у студентов;
- тему карточки, сочетание фильтров темы и готовности, пустую выдачу и сброс;
- явное сообщение о доступности откликов на опубликованную задачу с низким рейтингом;
- кнопки выбора и отклонения, несохранённые изменения и сохранённые статусы;
- выбор одной, двух и ни одной команды бизнесом, сохранение после reload;
- видимость решения студенту только по его собственному отклику.

При падении Playwright сохраняет screenshot и trace в `test-results/`.
Открыть trace: `pnpm exec playwright show-trace test-results/<test>/trace.zip`.
Артефакты исключены из Git: они могут содержать тестовые токены сессий.
Тесты выполняются без автоматических повторов, чтобы не скрывать нестабильность.

## Отдельная ручная проверка реального AI

Этот шаг не входит в автоматический прогон и требует настроенного AI-сервиса.
На тестовом стенде с реальным провайдером войдите как бизнес и повторите для ru,
kk, en с одним и тем же неполным описанием (например, обработка заявок из почты).

1. Введите описание на проверяемом языке. Язык вопросов определяется по описанию,
   независимо от языка интерфейса. Убедитесь, что получено минимум три понятных
   вопроса на языке описания, без смешения языков и выдуманных фактов.
2. Проверьте, что вопросы уточняют действительно недостающие данные: пользователей,
   материалы, результат, критерии, ограничения или контакт. Оцените естественность
   казахского и английского с носителем языка; наличие языка в ответе само по себе
   не доказывает качество перевода.
3. Ответьте своими словами. Переключите интерфейс, перезагрузите сохранённый
   черновик: язык вопросов и исходные тексты должны сохраниться.
4. Соберите карточку. Сверьте каждое поле с описанием и ответами: неизвестные
   сведения остаются пустыми, AI не добавляет факты. Проверьте её до публикации.
5. Зафиксируйте дату, модель/провайдера, язык, исходный текст, вопросы и замечания
   к смыслу/грамматике. Не включайте реальные персональные данные или секреты.

Автотесты подтверждают поведение приложения; качество языка реального AI оценивается
этой отдельной проверкой и не заявляется проверенным фиксированными ответами.
